# Case Study Template

## Artifact Structure
```
artifact/
├── case-study.md          # The full case study (1500-2000 words)
├── framework.md           # Extracted transferable framework (500-800 words)
└── application.md         # How framework applies to [company]'s challenge (500-800 words)
```

## case-study.md Template

```markdown
# [Title]: How [Action] Drove [Result] at [Company]

## The Challenge
[What the problem was — make it relatable to the target company's context]
[Scale: users, revenue, team size — from fact-set.md]

## The Initial Approach (and Why It Was Wrong)
[What was tried first — the pivot story]
[Why the obvious solution didn't work]

## The Insight
[The non-obvious realization — this is the earned secret]
[Why this insight required being in the trenches, not just analyzing from outside]

## The Solution
[What was actually built/shipped]
[Key technical and product decisions]
[Specifics that demonstrate depth: architecture, trade-offs, adoption strategy]

## Results
[Quantified outcomes — ALL from fact-set.md]
- [Metric 1]
- [Metric 2]
- [Metric 3]

## The Transferable Framework
[See framework.md — summarize the 3-5 step framework here]

## Applicability to [Target Company]
[See application.md — summarize how this maps to their challenge]
```

## Depth Requirements Checklist
- [ ] Every metric comes from fact-set.md
- [ ] The "insight" section contains a genuine earned secret
- [ ] The pivot story is honest (not just "we made the right call from the start")
- [ ] The framework is genuinely transferable (tested across at least 2 of Sujoy's roles)
- [ ] Application to target company references specific challenges from intel.md
- [ ] Acknowledges where the analogy breaks down (honesty builds credibility)
